# 2D / 3D 对比表及共同评价规则

本文件固定后续填写规则，不启动新训练，也不声称 2D 已达到目标。
主表在本项目 [README.md](../../README.md)，不再保留重复的 Markdown 副本。机器可读结果在 `support/comparison/metrics.json` 和 `metrics.csv`。
2D U-Net 是当前已提交的对照，2D Improved U-Net 只保留可选空栏，不代表同时开展新实验。

## 1. 三种范围分别报告

| 范围 | 数据覆盖与网格 | 可以填写什么 | 不可以怎么使用 |
| --- | --- | --- | --- |
| 完整体积 3D | 完整降采样 `[64,128,128]` | 已完成的 3D 测试结果 | 不能与原生 2D 局部切片得分直接判优劣 |
| 原生 2D 任务 | 每扫描 60 张原始有效切片，256×128 或 256×144 | 2D 完成后的原生测试结果；按扫描汇总 | 不能伪装成完整 3D 体积指标 |
| 共同区域 | 统一到 3D 网格 `[64,128,30]`，截取完整网格 W=49..78 | 对齐后的双方指标 | 不能只统一患者就忽略尺寸、翻转和空间采样差异 |

已确认 3D 在共同区域内的前列腺 TP/FP/FN 恰好与完整体积相同，所以 Dice 相同。
六类结果表显示其他类别并不相同。共同区域 CSV 没有记录 HD95 或器官交叉混淆计数，
这些栏留空，不能直接挪用完整体积的 6.50 mm、89、21。

## 2. 固定患者、病例和检查点

- 固定 26/6/6 位训练/验证/测试患者，与既有 3D 分组一致；测试 27 个扫描。
- 原生 2D 对应 8,700/2,340/1,620 张切片。数字患者 ID 与 3D 字母前缀 ID 的映射
  已核对，不能拿课程原有目录分组或朋友的分组替换。
- 3D 冻结权重 SHA256 保存在 `support/comparison/metrics.json`。
- 2D 检查点只按验证集选定；正式填写时补齐检查点哈希、模型配置及实际训练记录。
  不选择测试分数最高的轮次，不按测试表现决定是否换成 Improved 模型。
- 各模型的测试病例集合必须与表中已记录的 `test_case_ids`、`test_patient_ids` 相同。
  如某例评价失败，记录失败原因，不能悄悄删除后继续报告为 27 例。

## 3. 共同网格的方向与位置

先前对全部扫描键和部分实际像素的核对得到：

```text
course_2d_slice[i] = original_3d_volume[::-1, 98+i, :], i=0..59
```

它是原始 NIfTI axis 1 的冠状面带，切片内 axis 0 反向。课程 2D 样例的
identity affine 不能提供可靠的原始 mm 间距。

后续评价 2D 预测时按以下顺序操作，保持规则固定：

1. 用元数据的 `original_h/original_w/pad_right` 去掉预测补边；标签 255 不参与评价。
   此处固定对 argmax 后的整数标签做映射，不能根据测试分数改用另一插值方式。
2. 将切片第一轴翻转回来，再转置成 `(Z,X)`。**翻转必须在 nearest 降采样之前做**，
   避免取整带来的一个原始像素偏差。
3. 对于这批已审计的原始 Y=256、目标 W=128，3D 的 nearest 标签采样使用
   `source_Y=floor(W*256/128)`。共同区域 W=49..78 对应 Y=98,100,...,156，
   即原生 2D 索引 i=0,2,...,58，不是全部 60 个原生平面。
4. 每个选中平面在 `(Z,X)` 上用同一 nearest 规则降采样到 `(64,128)`，按 W 顺序堆叠，
   得到 `[64,128,30]`。原始 Z=144 的扫描也按自己的形状到 64，不能假定都为 128。
5. 使用完全相同的路径变换 2D GT，并与原始 3D GT 经 `dataset.py` 后截取的 GT
   **逐体素核对一致**。这是正式对比前的必需检查；当前还没有拿实际 2D 预测执行这一步。
   若不一致，停止填写双方对比表，先查病例、位置和变换，不能掩盖差异或改 GT。
6. 若新数据的 Y 尺寸、方向或映射不符，以上固定索引不适用，需要明确的新协议；
   不能把本次 256 宽数据的规则当作任意 NIfTI 的通用解法。

共同区域评价并不改变模型输入：3D 仍看完整体积，2D 仍逐张看原始切片。
这是两种已训练系统的比较，不是只改变卷积维度的严格消融。

## 4. 指标口径

- 前列腺为项目标签 5。先按扫描累计 60 张原生片或统一后的共同网格，再计算 Dice/IoU，
  最后对有效扫描平均；不平均 mini-batch Dice，也不把全部切片当成独立患者。
- 同时单列总体 TP/FP/FN 汇总后的 Dice、精确率、召回率及总体预测/GT 体积比。
  逐患者平均另列，避免多周扫描数不同导致权重含糊。
- 预测与 GT 都为空时记为未定义，并报告有效例数；单边为空的 Dice/IoU 为零。
- 共同区域 HD95 要从双方共同区域三维掩码重新计算，使用同一原始 affine 推导的
  近似降采样间距及既有双向边界 P95 定义。报告 ROI 裁剪，并检查前列腺是否触及截断面，
  避免把裁剪产生的边界当成完整器官边界。任一掩码为空则距离未定义，不填零。
- 膀胱/直肠侵入按共同区域 GT 类别与预测前列腺交集分别计数，不能从各类别 TP/FP/FN
  推出交叉混淆数；需要实际预测或完整混淆矩阵。
- 固定五例用于图示时，比较同一患者、周次、空间位置和颜色表；数值统计覆盖所有 27 例。
  同时展示好坏结果，不重新挑选只对某个模型有利的切片。

## 5. 参数和资源另表

目前 3D 的 351,206 参数、17.55 ms 前向中位延迟和 0.1364 GiB 推理分配来自
A100 40GB / BF16 的完整输入推理。不是训练显存或端到端吞吐。
2D 参数以最终检查点配置核实，时间以每扫描完整所需切片的推理计时，不能用一张片的
时间对一个三维体积的时间。比较时记录 GPU、精度、batch、预热和计时边界；硬件不一致
时只描述各自运行条件，不把差别归因于网络维度。

两个当前系统还存在宽度、深度、归一化、采样和训练策略差异：3D 为 base 8、三次池化、
InstanceNorm；2D 为 base 16、四次池化、BatchNorm。2D 逐片归一化，3D 逐体积非零
体素归一化。对齐评价区域只能修复评价覆盖问题，不能消除这些训练混杂因素。

## 6. 自动核查与填写状态

从项目目录运行 `python -m support.prepare_comparison`，只读取已归档 JSON/CSV：

- 重新用 TP/FP/FN 验算完整体积和共同区域的每例、每类 Dice/IoU。
- 重算逐扫描平均/标准差、逐患者平均、总体指标，与两份冻结摘要核对。
- 核对病例集合、患者数、完整体积 HD95 和侵入计数，保存来源文件哈希。
- 生成 `support/comparison/metrics.json`、`metrics.csv` 和 README 内主表，不另复制一份相同的 Markdown 表。
- 2D 未完成的数值使用 JSON null / CSV 空栏 / Markdown Pending，不拿验证值或合成值代替。

当前结果：3D 完整体积与共同区域重叠指标已填写；2D 原生及共同网格指标待独立测试；
2D Improved 未安排。没有新增训练、评价任务或后台监控。
